## R1. Форма источника истины: YAML-каталог + генератор Markdown

**Decision**: Единственный источник — `aiuc1/catalog.yaml`. Человекочитаемая карта
`docs/aiuc1-coverage.md` **порождается** из него чистой функцией. Руками Markdown не правится.

**Rationale**:
- SC-003 требует, чтобы машиночитаемая и человекочитаемая версии не расходились. Единственный
  надёжный способ — одна из них производная. YAML как источник, Markdown как рендер.
- YAML уже используется в проекте (`attacks/suite.yaml`) — единый стиль данных, знакомый читателю
  (Принцип I).
- Тест «рендер детерминирован и совпадает с зафиксированным файлом» превращает SC-003 в
  исполняемый гейт (Принцип IV).

**Alternatives considered**:
- Markdown как источник, YAML генерируется парсингом таблиц — парсинг Markdown хрупок,
  структурированные поля (partial-разбивка, binding) в таблицу ложатся плохо. Отвергнуто.
- JSON вместо YAML — машиночитаем, но хуже читается человеком при ручном заполнении 53 записей;
  YAML нативно комментируется. Отвергнуто в пользу YAML (агрегаты всё равно считаются кодом).
- Держать всё прямо в Python — теряется «данные отдельно от кода», каталог перестаёт быть
  артефактом, который можно дать не-программисту. Отвергнуто.

## R2. Проверяемость статуса `covered` против кода (SC-004)

**Decision**: Каждый контроль со статусом `covered` несёт поле `binding.scorecard_control` —
идентификатор существующего учебного контроля (`SEC-01`, `PRIV-02`, …). Тест
`test_covered_grounded.py` импортирует `scorecard/controls.py`, собирает фактическое множество
id контролей и падает, если хоть один `covered` ссылается на несуществующий id.

**Rationale**:
- SC-004 требует «ноль ложных covered, проверяемо против кода». Единственный честный способ —
  связать карту с реальным кодом тестом, а не декларацией.
- Это прямой аналог гейтов конституции фичи 001: карта не может соврать про покрытие, пока тест
  зелёный.

**Alternatives considered**:
- Ручная сверка при ревью — не воспроизводимо, разъедется со временем. Отвергнуто.
- Считать `covered` всё, что «касается пиллера» — размывает честность карты, ровно то, чего
  спека избегает. Отвергнуто.

## R3. Семантика статусов и `partial` (из clarify)

**Decision**: Ровно один базовый статус на контроль: `covered` / `technical-achievable` /
`doc-only`. Агрегация — по базовым статусам, сумма == 53. `partial` — булев модификатор для
mixed-контролей, с полями `partial_technical` и `partial_documentable`, описывающими две части.
`partial` в агрегацию по статусам не входит; считается отдельным счётчиком.

**Rationale**: зафиксировано в Clarifications спеки. Сохраняет чистую агрегацию (FR-009) и честно
показывает двойную природу mixed-контролей.
