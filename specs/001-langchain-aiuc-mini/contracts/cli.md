## `aiuc run`

Прогоняет набор атак против мишени и пишет trace. **Недетерминированная фаза** (вызывает LLM).

```
aiuc run [--guardrails / --no-guardrails] [--suite PATH] [--max-mutations N]
         [--attempt-timeout SEC] [--out DIR]
```

| Опция | Default | Смысл |
|---|---|---|
| `--guardrails / --no-guardrails` | `--no-guardrails` | защищённый или уязвимый режим (FR-011) |
| `--suite` | `attacks/suite.yaml` | фиксированный набор атак |
| `--max-mutations` | `2` | бюджет мутаций на атаку (FR-007) |
| `--attempt-timeout` | `60` | таймаут попытки; при превышении — вердикт `ERROR`, прогон продолжается (FR-015) |
| `--out` | `runs/` | корень артефактов |

**Выход**: `runs/<run_id>/trace.jsonl`. В stdout — путь к trace и краткая сводка
(попыток / успешных атак / ошибок).

**Exit codes**: `0` — прогон завершён (даже если атаки прошли: успешная атака это результат, а
не сбой инструмента); `1` — прогон не удалось начать (нет suite, не сконфигурирована модель).

**Контракт безопасности**: `run` MUST NOT изменить ничего вне `--out` и `Sandbox.root`
(Принцип II, SC-007).

## `aiuc score`

Строит scorecard по существующему trace. **Чистая, детерминированная фаза** — LLM не вызывается.

```
aiuc score RUN_DIR [--format md|json|both]
```

**Выход**: `scorecard.json` и/или `scorecard.md` в `RUN_DIR`.

**Контракт детерминизма** (Принцип IV, SC-006): для одного и того же `trace.jsonl` команда
MUST давать побайтово идентичный `scorecard.json` при любом числе запусков, на любой машине.
Отсюда: никаких timestamp'ов, абсолютных путей и host-специфичных данных в отчёте.

**Exit codes**: `0` — отчёт построен; `1` — trace отсутствует или невалиден.

Заметьте: exit code **не** зависит от того, сколько контролей провалено — `score` сообщает
результат, а не выносит суждение о том, приемлем ли он.

## `aiuc compare`

Сравнивает два прогона (обычно «без защиты» vs «с защитой») — то, чем измеряется SC-003.

```
aiuc compare BASELINE_DIR PROTECTED_DIR
```

**Предусловие**: у обоих прогонов совпадает `suite_hash`, иначе — ошибка (сравнивать прогоны на
разных наборах атак бессмысленно, FR-011).

**Выход**: таблица «доля успешных атак до/после», снижение в %, доля ложных блокировок (SC-004).

## `aiuc demo`

Полный учебный сценарий одной командой (SC-001): прогон без защиты → прогон с защитой →
scorecard'ы → сравнение.

```
aiuc demo [--suite PATH]
```

**Выход**: два каталога прогонов + итоговое сравнение в stdout. Это и есть «одна команда,
показывающая атака → защита → аудит».

## Конфигурация окружения

`.env` (шаблон — `.env.example`):

```
LLM_TARGET=anthropic:claude-haiku-4-5-20251001   # модель агента-мишени
LLM_REDTEAM=anthropic:claude-haiku-4-5-20251001  # модель red-team агента
ANTHROPIC_API_KEY=...                            # ключ активного провайдера
```

Формат строки модели — `provider:model` для `init_chat_model` (R3). Поддерживаемые провайдеры:
`anthropic`, `openai`, `ollama` (ставятся как extras). Смена провайдера MUST требовать правки
только `.env`, но не кода.

**Контракт**: API-ключи MUST NOT попадать в trace, scorecard или stdout.
