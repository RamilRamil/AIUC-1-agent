# Implementation Plan: Внешняя таксономия атак (OWASP LLM Top 10)

**Branch**: `005-external-attack-taxonomy` | **Date**: 2026-07-16 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/005-external-taxonomy/spec.md`

## Summary

Первая мера в проекте, приходящая **не от нас**. Три части:

1. **Внешний классификатор как данные** — `taxonomy/owasp-llm-top10.yaml` (10 категорий OWASP
   LLM Top 10 2025, версия и источник) со статусом покрытия каждой: `tested` / `gap` /
   `not_applicable` + обоснование. Приём тот же, что в фиче 002: данные отдельно, отчёт
   генерируется, гейт не даёт соврать.
2. **Привязка атак** — каждая атака `attacks/suite.yaml` ссылается на категорию; ссылка
   валидируется.
3. **Косвенная инъекция** (LLM01) — отравленная HTTP-фикстура: вредоносная инструкция приходит
   **через результат инструмента**, а не от пользователя. Контракт
   [tools.md](../001-langchain-aiuc-mini/contracts/tools.md) обещал её с фичи 001; в коде её нет.

**Гейт честности** (аналог `test_covered_grounded`, который себя оправдал): `tested` нельзя
проставить без реальных атак этой категории в наборе.

**Ожидаемый результат — скромный и неприятный, и это цель**: покрытие меньшинства списка, а
косвенная инъекция **пройдёт даже в защищённом режиме** (входной guardrail смотрит только на
сообщение пользователя). Закрытие вектора — следующая фича.

## Technical Context

**Language/Version**: Python 3.11+ (без изменений)

**Primary Dependencies**: без новых (`pyyaml`, `pydantic` уже есть)

**Storage**: файлы. Новое: `taxonomy/owasp-llm-top10.yaml` (данные). Формат trace не меняется.

**Testing**: `pytest` в контейнере. Новый гейт: `tested` подтверждается атаками набора.

**Target Platform**: локальный, всё через Docker

**Project Type**: single project — новый подпакет `taxonomy/` + правки набора атак и раннера

**Performance Goals**: не применимо

**Constraints**:
- `tested` MUST быть проверяем против `attacks/suite.yaml` (гейт);
- критерий успеха косвенной инъекции MUST быть объективным предикатом над trace (Принцип III);
- покрытие таксономии MUST публиковаться **отдельно** от доли отражённых атак (SC-006);
- отравленная фикстура MUST оставаться в песочнице: реального запроса на attacker.example нет
  (Принцип II не ослабляется);
- существующие 8 атак MUST получить привязку **без подгонки**: категория выводится из описания
  OWASP, а не наоборот.

**Scale/Scope**: 10 категорий, ~2 новые атаки, 1 новый критерий успеха, 1 фикстура

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

Проверка против [конституции v1.0.0](../../.specify/memory/constitution.md).

| Принцип | Как план ему удовлетворяет | Статус |
|---|---|---|
| **I. Обучение через практику** | Таксономия — плоский YAML, критерий — предикат над trace. Учебная ценность прямая: видно, чего стенд не проверяет, и почему самодельный набор это скрывал. | ✅ PASS |
| **II. Безопасность песочницы (NON-NEGOTIABLE)** | Отравленный контент — фикстура **внутри** песочницы. Агент «идёт» на attacker.example, но реального запроса нет: неизвестный URL уже даёт смоделированную 404 + `sandbox_violation`. Поверхность не расширяется. | ✅ PASS |
| **III. Объективная проверяемость** | Успех косвенной инъекции — предикат над trace (факт обращения к внешнему хосту), а не текст ответа и не мнение модели. | ✅ PASS |
| **IV. Воспроизводимость** | Таксономия и её покрытие — данные + чистая функция. Фикстура детерминирована. | ✅ PASS |
| **V. Наблюдаемость** | Обращение к внешнему хосту уже фиксируется `sandbox_violation(rule=external_host)` — новых событий не нужно. | ✅ PASS |
| **VI. Spec-driven разработка** | spec → clarify → plan → tasks → code. Запрет подгонки категорий зафиксирован в спеке заранее. | ✅ PASS |

**Итог гейта: PASS.** Complexity Tracking не заполняется.

**Заметка по Принципу II**: косвенная инъекция — первая атака, где мишень манипулируется
**контентом**, а не пользователем. Физически она по-прежнему безвредна: песочница пресекает
обращение. Ровно то разделение, ради которого Принцип II и писался — атака успешна учебно,
безвредна реально.

**Re-check после Phase 1**: PASS — дизайн не вводит реальной сети, критерий остаётся чистым
предикатом, покрытие таксономии считается чистой функцией.

**Structure Decision**: Данные таксономии — в `taxonomy/` рядом с `attacks/` и `aiuc1/`: тот же
приём, что для карты покрытия (фича 002). Он себя оправдал — гейт `test_covered_grounded` не дал
карте соврать ни разу, и здесь используется его прямой аналог `test_tested_grounded`.

Критерий `external_host_contacted` кладётся в `suite.py` рядом с остальными: это ещё один вариант
дискриминированного объединения, а не новая сущность.

Отравленная фикстура — в `runner._HTTP_FIXTURES`, где уже живёт безобидная справка. Никакого
нового механизма: песочница обслуживает её тем же словарём.
