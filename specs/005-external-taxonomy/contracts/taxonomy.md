# Contract — Таксономия и правила привязки

**Feature**: `005-external-taxonomy` | **Plan**: [../plan.md](../plan.md)

Контракт фиксирует, **как категория получает статус** и **что этот статус означает**. Смысл — не
дать внешней этикетке стать новым способом польстить себе.

---

## Форма файла `taxonomy/owasp-llm-top10.yaml`

```yaml
name: "OWASP Top 10 for LLM Applications"
version: "2025"
source: "https://genai.owasp.org/llm-top-10/ (сверено 2026-07-16)"

categories:
  - id: LLM01
    title: "Prompt Injection"
    status: tested
    rationale: "прямые инъекции с фичи 001; косвенная (через результат инструмента) — фича 005"
    attacks: ["direct-01", "direct-02", "indirect-01"]

  - id: LLM03
    title: "Supply Chain"
    status: not_applicable
    rationale: "у стенда нет цепочки поставки: ни плагинов, ни сторонних моделей в рантайме"
    attacks: []

  - id: LLM09
    title: "Misinformation"
    status: gap
    rationale: "галлюцинации не проверяются; groundedness — кластер output-filters карты (D001)"
    attacks: []
  # ... всего ровно 10 ...
```

## Правила статусов

| Статус | Когда ставить | Чем подтверждается |
|---|---|---|
| `tested` | атака **выведена из описания категории** и есть в наборе | `attacks[]` непусто, каждый id существует — гейт |
| `gap` | категория применима к архитектуре, но не проверяется | обоснование, что именно не проверяется |
| `not_applicable` | архитектура стенда не содержит предмета категории | обоснование через **свойство стенда** |

**Главный запрет**: `tested` не ставится потому, что «что-то похожее есть». Если проверяется лишь
отдалённо смежное — это `gap`. Иначе внешний список превращается в новый способ поставить себе
галочку, а фича теряет весь смысл.

**Правило `not_applicable`**: обоснование обязано указывать на **отсутствующую в стенде часть
архитектуры** (нет RAG → LLM08; не обучаем модель → LLM04). Формулировка «мы это не делаем» —
недостаточна: это `gap`.

## Проверяемые инварианты

| Инвариант | Тест | Требование |
|---|---|---|
| ровно 10 категорий, точный набор id `LLM01…LLM10` | `test_taxonomy_valid` | FR-001, SC-001 |
| у каждой категории есть статус и обоснование | `test_taxonomy_valid` | FR-002 |
| сумма по статусам == 10 | `test_taxonomy_valid` | SC-001 |
| `status=tested` ⇒ `attacks` непусто и **все id существуют в наборе** | `test_tested_grounded` | **FR-003, SC-002** |
| `status≠tested` ⇒ `attacks` пусто | `test_taxonomy_valid` | FR-002 |
| каждая атака ссылается на существующую категорию | `test_suite_taxonomy_refs` | FR-005, SC-003 |
| ссылка на несуществующую категорию отвергается на загрузке | `test_suite_taxonomy_refs` | FR-005 |
| косвенная инъекция удаётся в незащищённом прогоне | `test_indirect_injection` | SC-004 |

**Контракт честности** (FR-003): `test_tested_grounded` — прямой аналог `test_covered_grounded`
из фичи 002. Тот приём себя оправдал: карта покрытия ни разу не соврала, потому что статус нельзя
объявить — его можно только заслужить наличием механизма. Здесь то же самое: `tested` нельзя
объявить, его можно только заслужить наличием атаки.

## Отчёт `aiuc taxonomy`

```
OWASP Top 10 for LLM Applications (2025)
  tested:          4
  gap:             3
  not_applicable:  3
  проверяется 4 из 7 применимых классов (57%)

Карта: docs/attack-taxonomy.md
```

**Обязательное разделение** (FR-008, SC-006): этот отчёт **не смешивается** со scorecard.

- «проверяется 4 из 7 применимых» — про **широту**;
- «отражено 100% атак» (scorecard) — про **глубину** на той узкой полоске, что проверяется.

Вместе они читаются правильно: *стенд отражает все атаки из тех классов, которые вообще умеет
проверять, а умеет он меньшинство.* По отдельности каждая врёт: первая занижает, вторая льстит.

## Уточнённая оговорка (FR-009)

Была (фича 003):

> Набор атак и правила детекции созданы внутри проекта.

Стала:

> **Категории** атак взяты из внешнего списка (OWASP LLM Top 10, 2025), **нагрузки** написаны
> внутри проекта. Внешняя классификация показывает, каких классов атак стенд не проверяет вовсе;
> она не делает нагрузки представительными. Полное устранение самоподтверждаемости требует
> внешнего корпуса нагрузок.

Точнее и честнее: circularity **уменьшена** (структура пришла извне), но **не устранена**.
